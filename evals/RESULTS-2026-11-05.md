# Repeatability results, 2026-11-05

Four prompts, three runs each, old skill (snapshot) vs revised skill. Runs by Opus subagents told to write questions.md and stop if they needed the user. Programmatic checks plus Opus graders; full data in `../../newmont-skill-workspace/iteration-2/` and the review page `review-iteration-2.html`.

| Case | Old skill (3 runs) | New skill (3 runs) | What flipped before |
|---|---|---|---|
| underspecified-deck-asks-first | 4/6, 5/6, 4/6 | 6/6 ×3 | 7–8 questions, topics varied, deck name asked in 1 of 3, spelling and format asked every time |
| complete-brief-deck | 9/11, 9/11, 11/11 | 11/11 ×3 | two-line overrun fixed three different ways; stray .venv and proxy decks |
| html-one-pager | 7/7, 6/7, 7/7 | 7/7 ×3 | callout style split 2:1; no run looked at its page |
| fix-off-brand-deck | 7/7, 6/7, 6/7 | 7/7 ×3 | titles rewritten and credit line reordered in 2 of 3 |

Overall: 87% ± 12% → 100% ± 0%. Deck builds got faster (kit is now a file, not 200 lines to retype); HTML got slower because it now renders and looks.

What changed in the skill: an intake gate (must-have inputs vs decide-and-state defaults, how to ask, a worked example), a content-to-page-type table, rules for text that overruns a limit and for restyling without rewriting, a setup check for python-pptx, Open Sans and LibreOffice, the kit moved to `scripts/newmont_kit.py`, an executable checker `scripts/check_deck.py`, and a fixed reply format.

Found and fixed during testing: the first worked example asked about spelling, contradicting the intake rules, and all three runs copied it (runs kept in `_superseded`); `check_deck.py` exited silently without its helper module.

Caveats: Open Sans is not installed on this machine, so every rendered preview used a substitute serif font; python-pptx is not installed system-wide, so each run installed it its own way. The assertions are now saturated; the next round needs harder cases (content that must be split across pages, a photo-backdrop page, a request for an off-palette colour, "just go" after questions).

## Round two (harder cases), same day

Four new prompts, three runs each, new skill only. Review pages: `review-round2.html` (first pass) and `review-round2-reruns.html` (after the fixes, with the first pass as baseline).

| Case | First pass | What varied | After fix |
|---|---|---|---|
| off-palette-request | 5/5 ×3 | nothing material: teal on the top band, white eyebrow for contrast, departure stated | not rerun |
| photo-backdrop-and-phases | 6/6 ×3 | nothing: decks near-identical, kit methods used | not rerun |
| long-content-must-split | 6/8, 6/8, 7/8 | seven risks laid out three ways (table, two statement pages, plain two-column page); 6/7/6 slides | 8/8 ×3, identical 5-slide structure |
| just-go-with-placeholders | 5/6, 5/6, 6/6 | 6/8/8 slides, different outlines, covers hand-built | 6/6 ×3, one 8-page outline, half the run time |

Fixes made: a `lead_in_list` page in the kit for four or more lead-in items (never a table for sentences), `statement()` without columns for a claim that stands alone, photo placeholders inside the kit (`cover`/`closing`/`picture` accept `None`), a default 8-page outline for topic-only requests, an "exactly three points" rule for three-column pages, and a rule to write one-sentence titles from the content and list them as assumptions when the brief gives none.

What still varies: the wording of titles a run writes when the brief gives none, and incidental units in placeholder tables. Both are stated in the reply, so the person can change them in one line.

## Round three: financial template case

Case `financial-template-two-slides` uses the exact prompt that produced the original two-slide template. After adding `kpi_tiles` and `fin_table` to the kit and the "Financial results pages" and "Templates" sections to the skill, three runs scored 7/7 each with the same two-page structure, the same four tiles and the same four guidance rows. Still varying, now pinned in the skill but not rerun: the Δ column basis (prior quarter), the table's y under a subtitle (100), 12 pt body on the summary page, and the footnote staying at 10 pt.
